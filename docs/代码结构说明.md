# 代码结构说明

> 这份文档对应仓库 `src/` 下真实存在的文件。逐块的完整清单（131 个块、体积、注释头标题）见 **[BLOCKS.md](./BLOCKS.md)**，机器可读版本见 [blocks.json](./blocks.json)。

## 为什么是「分层 + 拼装」而不是「拆成 ES Module」

线上产物是一个 **单文件 HTML**：CSS、JS、资源、webpack chunk 全部内联，靠 `DEFLATE` 压缩 + `Blob` 注入在启动期解压，秒开且零请求。

这套机制有三条硬约束（原文件头部注释里也写着）：

1. **B20 资源表 与 ④ 构建层不能格式化** —— 它们靠换行分段、字节长度、单行超长文本工作，任何缩进或换行都会让惰性解码失效；
2. **`bl-embedded-bundle` 的文本里不能增删任何字符** —— B13 用 `indexOf` 按换行建索引，多一个字符，105 段全部错位；
3. **不能在 B00 之前插脚本** —— 性能总线必须最先接管 DOM 观察。

所以这里不做「改写成 import/export」的破坏性重构，而是：

```
src/  按「层」保存原始片段（逐字节保真）
  ↓  scripts/build.mjs 按模板顺序字符串拼接（不压缩、不转译、不加空白）
dist/index.html  与原始单文件逐字节一致
```

`npm run verify` 会比对 `docs/blocks.json` 里记录的基线 sha256 —— 只要拆分过程没吞字节，产物就和原文件一模一样。改过分层源码后，指纹自然会变，改用 `npm run check` 做结构与可达性自检。

## 目录映射

| 目录 | 层 | 内容 | 关键块 |
| --- | --- | --- | --- |
| `src/index.html` | 模板 | 唯一入口。它是「骨架 + 131 个 `{{include}}` 占位」，本身不含业务代码 | — |
| `src/boot/` | ① 启动层 | DEFLATE 同步解码器、性能总线、同步注入总线、加载屏 HTML/CSS/逻辑 | B00 B01 B02 B03 B04–B07 B107 |
| `src/assets/` | ② 资源层 | `__RES__` 资源表（静态资源惰性 inflate 成 data URI）、11.9 MB 主 bundle 文本、3 个模板源码 | B20 B9 |
| `src/bridge/` | ③ 桥接层 | 单 bundle 索引读取（105 段）、chunk → Blob、资源 URL 重写 | B13 B14 B15 |
| `src/vendor/chunks/` | ④ 构建层 | webpack 产出的 12 个 chunk 原文（`text/plain` 内联，惰性解码） | `bl-ec-0` … `bl-ec-11` |
| `src/vendor/loaders/` | ④ 构建层 | 每个 chunk 的 300 字节装载器：解码 → 造 `<script>` → 插到 `currentScript` 后面 | `data-bilup-src` |
| `src/patches/js/` | ⑤ 补丁层 | 58 个功能补丁（主题、Dock、舞台、工具箱、设置、引导…） | B28 B32–B75 B82–B99 |

| `public/` | 静态透传 | 原样复制到 `dist/`：`_headers`、`favicon.svg` | — |
| `scripts/` | 构建工具 | 零依赖 Node 脚本：import / build / dev / check | — |
| `docs/` | 文档 | 本文件、块清单、部署说明 | — |

## 启动时序（读代码请按这个顺序）

```
<html><head>
  B00  DEFLATE 同步解码器         ← 必须先定义，后面全靠它
  B01  性能总线                   ← 接管 rAF / 定时器 / DOM 观察
  B107 同步注入总线 v3            ← 后续补丁的排队执行器
  B02/B03  原生启动屏 + 加载界面样式
  B85  扩展库卡片 LOGO（就地内联，避免解码等待）
</head><body>
  B04–B07  加载页主题预判 / 收起兜底 / 单文件标记
  B20      __RES__ 资源表          ← 惰性 getter，用到才 inflate
  B9       bl-embedded-bundle     ← 11.9 MB、105 段合并压缩源码
  B13–B15  桥接：索引 / Blob / URL 重写
  bl-ec-0 … bl-ec-11 + 装载器      ← 12 个 webpack chunk 依次注入
  B28 … B99                        ← 35+ 轮补丁，按依赖顺序排列
</body></html>
```

`B` 编号即「注入轮次」，编号越大越晚执行、优先级越低。跳号（如 B30/B31）是历史遗留，不代表缺失。

## 改一处代码该动哪个文件

| 想改的东西 | 动这里 | 注意 |
| --- | --- | --- |
| 加载屏文案 / 动画 | `src/boot/003-b02.css`、`004-bl-loading-css.css`、`008-b06.js` | 纯样式，安全 |
| 某个主题 / 皮肤 | `src/patches/css/*` 里对应块 | 片段自带 `[Bxx]` 头，别删 |
| 某个功能补丁 | `src/patches/js/*` 对应块 | 改完先 `npm run dev` 看控制台 |
| 品牌资源（logo、图标） | `src/assets/010-b20.js` 的 `__RES__` 表 | 资源是 base64+deflate，需按原格式替换，不要格式化整个文件 |
| webpack chunk | `src/vendor/chunks/*` + `loaders/*` | 两者是配对的，解码长度写在装载器参数里，改一个必须改另一个 |
| 新增一层补丁 | 新建 `src/patches/js/NNN-bxx.js`，并在 `src/index.html` 末尾按顺序加 `<script>{{include …}}</script>` | 顺序即执行顺序 |

## 命名约定

- `NNN-` 是**全局顺序号**（等于它在 `src/index.html` 中的位置），改名不会影响构建，重排会。
- 后缀优先取原块的 `id`（如 `bl-dock-fix-css`），其次取 `[Bxx]` 标记，再次取 webpack chunk 名。
- `.txt` 后缀 = `text/plain` 内联载荷（不许被当 JS 解析），`.js`/`.css` = 可读源码。

## 常见坑

- **不要**用 Prettier / ESLint `--fix` 跑 `src/assets/` 和 `src/vendor/`，会把 20 MB 的单行文本拆行，直接让站点白屏。
- **不要**给 `{{include}}` 加缩进或换行，它是按字节替换的；多一个空格就多一个字节。
- 新增文件后若 `npm run check` 报「孤儿块」，说明模板里漏了引用 —— 这正是自检存在的意义。
